# v0.2.0 Feature Design

> 对应里程碑：**M3-M4 — 异构 + Agent 基础设施**
> 主线目标：**DeepSeek-V3 671B 跑通在 4090 + 64GB DRAM；Anthropic API + 磁盘 KV + Metal 后端齐备。**
> 时间窗口：第 10-15 月（v0.1.x 完成之后）

---

## Part A — 版本叙事

### 版本目标

v0.2.0 是 rsLLM 的**第一个重大分水岭**。完成它意味着：
1. 用户能在消费级硬件（24GB GPU + 64GB RAM）上跑 DeepSeek-V3
2. rsLLM 在 agent 工作流（Claude Code / opencode）上是 LM Studio / ollama 之外的可选项
3. Mac 用户能以 Metal 后端跑 70B+ 模型

### 本版本范围（In Scope）

1. cudaLaunchHostFunc 异构调度（FEATURE_019）
2. AMX / AVX512 CPU 内核（FEATURE_020）
3. DeepSeek-V2/V3（MLA + MoE）（FEATURE_021）
4. Anthropic Messages API（FEATURE_023）
5. Tool calling 双协议（FEATURE_024）
6. 推测解码（FEATURE_026）
7. **磁盘 KV cache 完整版**（FEATURE_031；简化版 F022 已在 v0.1.8 完成）
8. **Metal 完整版**（FEATURE_032；基础内核 F025 已在 v0.1.6 完成）

> **注**：原 F022（磁盘 KV）和 F025（Metal）在 2026-05-11 review 后拆 stage——简化版/基础版在 v0.1.x 已交付，本版本是完整版补齐。

### 验收标准（版本级）

- ✅ DeepSeek-V3 IQ2 在 4090 + 64GB DRAM 上 decode ≥ 8 t/s
- ✅ 磁盘 KV cache 命中后首 token 延迟 ≤ 100ms
- ✅ Anthropic Messages API 通过 Claude Code 真实 agent 工作流冒烟测试
- ✅ Metal 后端 Llama 70B Q4 在 M3 Max 上 ≥ 10 t/s

## Part B — Per-Feature 设计

> v0.2.0 各 feature 的详细 6 节设计将在 v0.1.x 系列完成后、本版本启动前补全。当前提供**占位草稿**，列明每个 feature 的核心思路与借鉴源，避免实施时偏离。

---

### FEATURE_019: cudaLaunchHostFunc 异构调度

#### 需求概述
通过 `cudaLaunchHostFunc()` 把 CPU 工作（cold MoE experts）挂到 CUDA stream 上，实现 CPU/GPU 真正异步并行，无需 mutex 同步。

#### 借鉴来源
- ktransformers `kt-kernel/cpu_backend/cpuinfer.h`（Apache 2.0 致谢）

#### 占位草稿
- 影响范围：`rsllm-cal` 加 `submit_host_fn` API，`rsllm-backend-cuda` 通过 `cudarc` FFI 调 `cudaLaunchHostFunc`
- 技术方案：CPU 任务队列 + NUMA 感知 worker pool（hwloc/libnuma 绑定）
- 验收：与纯 GPU 路径性能差距 ≤ 15%（说明 CPU 工作充分隐藏）

_完整 6 节设计待 v0.2.0 启动前补全。_

---

### FEATURE_020: AMX / AVX512 CPU 内核

#### 需求概述
Intel Sapphire Rapids+ CPU 上用 AMX tile 指令加速 MoE expert FFN。AVX-512 BF16 作为兜底。

#### 借鉴来源
- ktransformers `kt-kernel/operators/amx/`（Apache 2.0 致谢）
- ggml CPU AVX-512 路径（MIT 致谢）

#### 占位草稿
- 影响范围：新增 `rsllm-backend-cpu-amx` crate（Linux x86_64 only，cfg feature）
- 技术方案：CRTP → Rust trait 单态化；启动期 CPUID 探测；64 字节对齐
- 验收：Sapphire Rapids AMX 路径 ≥ AVX-512 路径 1.5×；启动期能自动选最优变体

_完整 6 节设计待 v0.2.0 启动前补全。_

---

### FEATURE_021: DeepSeek-V2/V3 支持

#### 需求概述
支持 DeepSeek-V2/V3/R1 架构：Multi-Latent Attention（MLA）+ MoE（256 routed + 1 shared）+ Hyper-Connection（V3）。

#### 借鉴来源
- ktransformers `archive/ktransformers/operators/attention.py` `get_absorbed()`（Apache 2.0 致谢）
- ds4 metal kernels `dsv4_*.metal`（MIT 致谢）

#### 占位草稿
- 影响范围：`rsllm-models` 新增 `deepseek_v2.rs` / `deepseek_v3.rs`
- 技术方案：
  - MLA 吸收：预计算 `q_absorb` / `out_absorb`，KV 保持压缩态
  - MoE 路由：top-K=6/256，hash routing（前 3 层）+ sigmoid routing
  - Hyper-Connection（V3 only）：4 streams + Sinkhorn 混合
- 验收：能跑 DeepSeek-V3 671B IQ2 模型，与官方 API 输出在 1000 token 上 logprob 一致率 ≥ 99%

_完整 6 节设计待 v0.2.0 启动前补全。_

### FEATURE_023: Anthropic Messages API

#### 需求概述
支持 `POST /v1/messages` 端点（Anthropic Claude API 兼容），SSE 流式 + 工具调用 + thinking 模式。能作为 Claude Code 的本地后端。

#### 借鉴来源
- ds4 `ds4_server.c` Anthropic 端点实现（MIT 致谢）
- Anthropic 官方 API 文档（行为参考）

#### 占位草稿
- 影响范围：`rsllm-server` 新增 messages 路由
- 技术方案：内部统一 `ChatRequest` 抽象，messages 端点是适配层（输入解析 + 输出格式化）
- 验收：Claude Code 切换 `ANTHROPIC_BASE_URL` 到 rsLLM 后能完成 10 轮 agent 工作流

_完整 6 节设计待 v0.2.0 启动前补全。_

### FEATURE_024: Tool calling

#### 需求概述
支持 OpenAI 风格 `tools` 字段和 Anthropic 风格 `tool_use` block。模型输出工具调用时，渲染对应协议格式。

#### 借鉴来源
- ds4 DSML 工具格式映射（MIT 致谢）
- OpenAI / Anthropic 官方 API 文档

#### 占位草稿
- 内部表示：`ToolCall { id, name, arguments }`
- 入口：OpenAI tools / Anthropic input_schema 双向解析
- 出口：根据请求源协议渲染回去（rax 风格 ID 映射保证 byte-identical 替放）
- 验收：双协议各 10 个工具调用场景测试通过

_完整 6 节设计待 v0.2.0 启动前补全。_

### FEATURE_026: 推测解码

#### 需求概述
选 MTP / Eagle / Medusa 之一实现推测解码，提速 1.4× 以上。

#### 借鉴来源
- ds4 MTP 实现思路（MIT 致谢）
- Eagle / Medusa 论文

#### 占位草稿
- 影响范围：`rsllm-scheduler` 加推测解码路径
- 技术方案（待选）：
  - 选项 A：MTP（draft model 独立 GGUF，与主模型同架构小版本）
  - 选项 B：Eagle（共享主模型权重，独立 draft head）
  - 选项 C：Medusa（多 head 并行预测）
- 验收：Qwen 32B + 1.5B draft 上提速 ≥ 1.4×

_完整 6 节设计待 v0.2.0 启动前补全。_

### FEATURE_031: 磁盘 KV cache 完整版

#### 需求概述
在 v0.1.8 简化版（cold checkpoint only）基础上，加入：
- **Continued checkpoint**：会话进行中阶段性保存，崩溃恢复
- **Tool call replay map**：rax 风格 tool call ID → DSML 原文映射，保证 byte-identical 复现（参考 ds4_server.c 的 tool call replay 机制）
- **会话淘汰策略**：LRU + 优先级队列

#### 借鉴来源
- ds4 `ds4_server.c:4791-5200` KV disk policy 完整实现（MIT 致谢）
- ds4 README 第 373-460 行 KVC 文件格式扩展（MIT 致谢）

#### 占位草稿
- 影响范围：扩展 `rsllm-kvcache` 加 KVC v2.1 文件格式
- KVC v2.1 扩展字段：tool_call_replay_map（变长尾部）
- 验收：与 Claude Code 真实 agent session 跑 30 分钟工具调用工作流，每次 tool call 输出 byte-identical 可复现

_完整 6 节设计待 v0.2.0 启动前补全。_

### FEATURE_032: Metal 完整版

#### 需求概述
在 v0.1.6 基础内核之上，加入：
- **Flash Attention**（v1/v2/v3 思路移植到 Metal）
- **MoE matvec**（IQ2_XXS / Q2_K / Q4_K 专家权重的 Metal kernel）
- **FP8 (E4M3FN) KV cache 量化**（参考 ds4 `metal/dsv4_kv.metal`）
- **Hyper-Connection kernel**（DeepSeek-V3 用）

#### 借鉴来源
- ggml `ggml-metal.m`（MIT 致谢，主要参考源）
- MLX `mlx/backend/metal/`（MIT 致谢）
- ds4 `metal/*.metal` 全套，特别是 `dsv4_kv.metal`、`dsv4_hc.metal`、`moe.metal`、`flash_attn.metal`（MIT 致谢）

#### 占位草稿
- 影响范围：扩展 `rsllm-backend-metal` crate
- 关键 kernels：`flash_attn.metal`、`moe.metal`（IQ2_XXS + Q2_K + Q4_K）、`dsv4_kv.metal`（FP8 KV）、`dsv4_hc.metal`（HC）
- 验收：Llama 70B Q4 在 M3 Max 128GB 上 ≥ 10 t/s；DeepSeek-V3 IQ2 在 M3 Ultra 512GB 上 ≥ 20 t/s

_完整 6 节设计待 v0.2.0 启动前补全。_
