## Part A — 版本叙事

### 版本目标（重定位后）

v0.1.0 是 **ds4 在 Rust 上的等价复刻**，但硬件目标比 ds4 多一台：

```sh
# Mac M3 Ultra 上：
$ rsllm chat -m /path/to/deepseek-v4-flash-q4k.gguf
rsllm> 你好，介绍一下自己。
我是 DeepSeek V4 Flash …（流畅输出，Metal 加速，~20-30 tok/s）

# AMD Ryzen AI Max+ 395 Linux 上：
$ rsllm chat -m /path/to/deepseek-v4-flash-q4k.gguf
rsllm> 你好，介绍一下自己。
我是 DeepSeek V4 Flash …（CPU AVX-512，约 ~3-8 tok/s decode，可用但慢）
```

**等价于 ds4** 意味着：
- 同一份 DS V4 Flash GGUF（Q2_K + Q4_K + IQ2_XXS 混合量化，约 140-160GB）能被读懂
- 三级 KV cache 行为与 ds4 数值对齐
- MLA + HC（Sinkhorn 20 轮迭代）权重应用正确
- 256 MoE expert 路由（前 3 层 hash 路由，其余层 top-6）正确
- JoyAI 状态机分词与 ds4 输出 byte-for-byte 一致
- 三种思考模式（think / think-max / nothink）prompt 模板与 ds4 一致

### 本版本范围（In Scope）

1. **F001** Cargo workspace 骨架 ✅ Completed
2. **F002** GGUF 解析器（已完成 9 种 dequant，补 Q2_K / IQ2_XXS / Q8_K / FP8 E4M3 共 4 种）
3. **F003** JoyAI 状态机分词器（DS V4 vocab，无 HF crate）

7. **F007** 采样器（greedy / temperature / top-k / top-p / min-p / **think_mode**）
8. **F008** CLI（linenoise REPL + 斜杠命令 + `inspect` / `--dump-tokens` / `--dump-logprobs`）

### MVP 主流程

```
用户：rsllm chat -m deepseek-v4-flash-q4k.gguf
   │
   ▼
[F008 CLI] 解析命令行 → 启动 linenoise REPL
   │
   ▼
[F001/F002 Engine] 加载模型
   │
   ├─► [F002 GGUF] mmap 文件 + 解析 metadata + tensor index
   │      • Mac: MAP_PRIVATE（避免 Darwin VM bug）
   │      • AMD/Linux: MAP_SHARED（128GB 内存 + 2TB SSD mmap 冷专家）
   ├─► [F003 Tokenizer] 从 GGUF 加载 vocab + merges，构造 JoyAI 状态机
   ├─► [F005 DS V4 Flash] 校验固定形状（43 层、4096 emb、129280 vocab、256 expert）
   │      → 实例化 model graph（MLA + HC + MoE topology）
   └─► [F004 Backend] 选定平台：
          • Mac arm64 → rsllm-backend-metal（主） + NEON CPU（验证）
          • Linux x86_64 (AMD Strix Halo) → rsllm-backend-cpu AVX-512 + VNNI
   │
   ▼
REPL 循环：
  用户输入 → [F003] tokenize + JoyAI 预分词 → token IDs
       → [F008] 注入 BOS + system + user + assistant + (think/nothink 前缀) token
       → [F006] 重置或继承 KV cache
       ▼
  生成循环：
    [F005 DS V4.forward]
      → for each layer:
          HC Sinkhorn 20 轮 mix
          MLA: Q/KV LoRA 投影 → norm → 头分裂
          KV 写入：raw SWA ring 或 compressed pool（按 token 位置）
          attention（含 ratio-4 indexer top-512 稀疏路径）
          MoE：前 3 层 hash 路由，其余层 top-6 + shared expert
          SwiGLU FFN
          HC post-合并
    [F004] 调用 SIMD kernel（NEON / AVX-512 / Metal）
    [F006] KV cache 状态前进
    [F007] sample(logits) → token i+1
    [F003] decode → 字符串 → 流式输出
  直到 EOS（｜end▁of▁sentence｜）或用户 Ctrl+C
   │
   ▼
保持 REPL 不退出（下一轮继续 KV，命中相同 prefix 复用）
```

### FEATURE_003: JoyAI 状态机分词器（ds4 复刻）

#### 需求概述

复刻 ds4 的 BPE tokenizer，用于 DeepSeek V4 Flash（`tokenizer.ggml.pre = "joyai-llm"`）。**不依赖** HuggingFace `tokenizers` crate——JoyAI 预分词器有 negative lookahead，纯 Rust `regex` crate 不支持；ds4 选择手写 UTF-8 状态机，70 行 C 代码就覆盖全部规则。我们做 Rust 等价 port。

#### 影响范围
- crate：`rsllm-tokenizer`
- 文件：
  - `crates/rsllm-tokenizer/src/lib.rs`
  - `crates/rsllm-tokenizer/src/vocab.rs`（GGUF metadata → vocab + merges 加载）
  - `crates/rsllm-tokenizer/src/joyai_pretokenize.rs`（状态机预分词）
  - `crates/rsllm-tokenizer/src/bpe.rs`（合并排序）
  - `crates/rsllm-tokenizer/src/special.rs`（特殊 token：BOS/EOS/User/Assistant/think/DSML）
  - `crates/rsllm-tokenizer/src/chat.rs`（DS V4 chat prompt 拼装，3 种 think 模式）

#### 技术方案

##### JoyAI 预分词规则（直接 port 自 `ds4.c:13791-13879`）

8 条规则的 Rust 状态机：

1. `\p{N}{1,3}`：连续 1-3 个数字
2. `[CJK / Hiragana / Katakana]+`：CJK 字符连续
3. `[ASCII 标点/符号][A-Za-z]+`：标点后跟字母（含标点）
4. `[^\r\n\p{L}\p{P}\p{S}]?[\p{L}\p{M}]+`：字母 + 修饰符
5. ` ?[\p{P}\p{S}]+[\r\n]*`：标点 + 可选换行
6. `\s*[\r\n]+`：纯换行
7. `\s+(?!\S)`：**带 negative lookahead**，"空格末尾"（用 last_newline_end 状态变量实现）
8. `\s+`：兜底空格

每条规则在 `pos` 推进时设置一个新的 `start..pos` 片段，emit 给 BPE。

##### BPE 合并算法

直接 port 自 `ds4.c:13881-13931`：

1. 从 GGUF `tokenizer.ggml.merges` 读 string array，每个 `"a b"` 拆为 `(a, b)` pair → 哈希表 `merge_rank: HashMap<(String,String), u32>`
2. 把预分词片段切成 UTF-8 字符，逐字符 push 到 token list
3. 反复扫描 adjacent pair，找 `merge_rank` 最低的（最早入表 = 最优先合并），合并
4. 直到没有可合并的 pair

##### 特殊 token 处理

DS V4 Flash 特有 token，从 vocab 中字符串查找 ID（fail-fast 缺失则报错）：

```
<｜begin▁of▁sentence｜>     → bos_id
<｜end▁of▁sentence｜>       → eos_id
<｜User｜>                    → user_id
<｜Assistant｜>               → assistant_id
<think>                       → think_start_id
</think>                      → think_end_id
｜DSML｜                      → dsml_id（tool calling 用，v0.1.0 暂不用）
```

##### Chat prompt 拼装（3 种 think 模式，参照 `ds4.c:13943-13964`）

```
[bos_id]
  [think-max 时插入特定 prefix 文本，经 BPE]
  [system 文本，经 BPE，可空]
  [user_id]
  [user 文本，经 BPE]
  [assistant_id]
  [think_mode 时插入 <think> token，nothink 时插入 </think>]
```

#### 接口契约

```rust
pub struct Tokenizer { /* opaque */ }

pub enum ThinkMode { Disabled, Enabled, Max }

pub enum Role { System, User, Assistant }
pub struct Message { pub role: Role, pub content: String }

impl Tokenizer {
    /// 从 GGUF metadata 构造（必需 tokenizer.ggml.pre == "joyai-llm" 等校验）
    pub fn from_gguf(meta: &Metadata) -> Result<Self, Error>;

    /// 纯文本 → token IDs（含 JoyAI 预分词 + BPE）
    pub fn encode_text(&self, text: &str) -> Vec<u32>;

    /// 单 token / 多 token → 字符串（流式输出用）
    pub fn decode(&self, ids: &[u32]) -> String;

    /// DS V4 chat prompt 拼装，自动注入 BOS / 角色 token / 思考模式 token
    pub fn encode_chat(
        &self,
        system: Option<&str>,
        user: &str,
        think_mode: ThinkMode,
    ) -> Vec<u32>;

    pub fn bos_id(&self) -> u32;
    pub fn eos_id(&self) -> u32;
}
```

#### 借鉴策略
- `joyai_pretokenize.rs` header：`// Ported by reference from ds4.c:13791-13879 (MIT, The ds4.c authors)`
- `bpe.rs` header：同上，引 `ds4.c:13881-13931`
- `chat.rs` header：引 `ds4.c:13943-13964`

#### 实现步骤
1. 实现 vocab 加载（GGUF tokenizer.ggml.tokens + .merges → 哈希表）
2. 实现 8 条 JoyAI 规则的状态机（其中 rule 7 用 last_newline_end 变量实现 lookahead）
3. 实现 BPE 合并循环
4. 实现特殊 token 查找
5. 实现 chat prompt 拼装（3 种 think 模式）
6. 单元测试：JoyAI 规则逐条覆盖 + BPE 合并 + 特殊 token 不被分割
7. 一致性测试：100 个 prompt 与 ds4 输出 byte-for-byte 对比

#### 验收标准
- ✅ 100 个 prompt（含中文、代码、Unicode、emoji）encode 结果与 ds4 完全一致（token id 序列相同）
- ✅ 3 种 think 模式的 chat prompt 拼装与 ds4 完全一致

### FEATURE_004: CPU 算子（DS V4 Flash 特化 + 双 SIMD）

#### 需求概述

为 DeepSeek V4 Flash 推理实现必需的 CPU 算子集。**不做通用 GEMM 库**——所有 kernel 都按 DS V4 Flash 的 tensor 形状特化。SIMD 双路径：
- **ARM NEON dotprod**（Apple Silicon，作为 Metal 主路径的数值验证 / fallback）
- **x86 AVX-512 + VNNI**（AMD Ryzen AI Max+ 395 Strix Halo 主路径；Zen 5 完整支持 AVX-512）

#### 影响范围
- crate：`rsllm-backend-cpu`
- 实现 `rsllm-cal::Backend` trait
- 借鉴：`ds4.c:42-43, 324-361, 2727-2781, 3277-3297`（NEON 路径）+ ggml `ggml-cpu-x86.c`（AVX-512 idiom，MIT）

#### 技术方案

##### 算子清单（v0.1.0 范围）

| 算子 | DS V4 Flash 用途 | NEON impl | AVX-512 impl |
|---|---|---|---|
| `matmul_q8_0_batch` | prefill batched matmul（按 token batch） | `vdotq_s32` | `_mm512_dpbusd_epi32` |
| `quantize_q8_0_activation_batch` | matmul 前激活量化 | NEON 标量+SIMD | AVX-512 |
| `matmul_q4_k_q8_k` | MoE routed expert (Q4_K weight × Q8_K activation) | 借鉴 ds4 | 借鉴 ggml |
| `matmul_q2_k_q8_k` | MoE routed down expert (Q2_K) | 借鉴 ggml | 借鉴 ggml |
| `matmul_iq2_xxs_q8_k` | MoE routed gate/up expert (IQ2_XXS) | 借鉴 ds4 | 借鉴 ggml |
| `matmul_f16` | dense 路径（attn proj / shared expert） | `vfmaq_f32` | `_mm512_fmadd_ps` |
| `rmsnorm` | 每层 norm，eps=1e-6 | NEON | AVX-512 |
| `rope_yarn` | Q/K 旋转位嵌入，64 维尾部 + YaRN（freq_base=160000） | NEON | AVX-512 |
| `swiglu` | SwiGLU 激活（clamp exp=10） | NEON | AVX-512 |
| `softmax_attn` | attention softmax（带 mask） | NEON | AVX-512 |
| `sinkhorn_mix_20iter` | **HC mix 权重计算（20 轮迭代）** | NEON | AVX-512 |
| `argmax` | greedy 采样辅助 | NEON | AVX-512 |
| `parallel_for` | 任务并行（基于 `rayon`） | rayon | rayon |

##### Q8_0 Batched Matmul Idiom（直接 port 自 `ds4.c:3277-3297`）

```
prefill 入口：
  1. quantize_q8_0_activation_batch(x[n_tok, in_dim], xq[n_tok, in_dim], xscale[n_tok])
  2. for each out_channel (parallel via rayon):
       for each token t in 0..n_tok:
         int32 dot = vdotq_s32(weight[out_ch], xq[t])  // NEON
                  or _mm512_dpbusd_epi32(weight[out_ch], xq[t])  // AVX-512
         out[t, out_ch] = (dot as f32) * wscale[out_ch] * xscale[t]
```

这是 ds4 在 ARM 上跑得动 284B 模型的核心 idiom，**必须忠实复刻**。AVX-512 VNNI 的 `_mm512_dpbusd_epi32` 与 NEON `vdotq_s32` 语义 1:1 对应。

##### Sinkhorn 算法（HC mix 权重，`ds4.c:4136-4169`）

每层前后各跑一次，N_HC=4 份残差流，20 轮迭代收敛到双随机矩阵。Rust port 用 NEON 平方根/除法 intrinsics 优化。

##### Backend trait 实现

```rust
impl Backend for CpuBackend {
    type Buffer = CpuBuffer;
    type Stream = CpuStream;
    fn capability() -> BackendCapability {
        BackendCapability {
            arch: cfg!(target_arch = "aarch64").then_some("neon")
                .or_else(|| cfg!(target_arch = "x86_64").then_some("avx512"))

    fn dispatch(&self, op: KernelOp, args: KernelArgs, stream: &CpuStream) { /* ... */ }

```

SIMD 分发用 runtime detection（`is_x86_feature_detected!("avx512vnni")` / `std::arch::is_aarch64_feature_detected!("dotprod")`），fallback 标量。

#### 接口契约

各算子按内部 enum `CpuOp` 分发；公开 API 是 `Backend::dispatch`。借鉴源文件 header 双重署名。

#### 实现步骤

1. 实现 `CpuBuffer` / `CpuStream` / `Backend` 骨架 + 标量 fallback
2. 实现 NEON 路径（macOS arm64 上测试）：matmul_q8_0_batch / quantize_q8_0 / matmul_f16
3. 实现 AVX-512 + VNNI 路径（Linux x86_64 上测试，需 Zen 5 或 Intel Sapphire Rapids+）
4. 实现 RMSNorm / RoPE-YaRN / SwiGLU / softmax
5. 实现 Q4_K / Q2_K / IQ2_XXS matmul（依赖 F002.1）
6. 实现 Sinkhorn 20 轮迭代
7. 单元测试：每个算子 NEON 与 AVX-512 输出对齐到 1e-4，并与 ds4 reference 对齐

#### 验收标准

- ✅ `matmul_q8_0_batch` 在 Apple M3 Max 上 prefill 吞吐 ≥ ds4 同硬件 60%（NEON 直 port，无 SIMD 调优）
- ✅ `matmul_q8_0_batch` 在 AMD Strix Halo 上 AVX-512 vs 标量 ≥ 3× 加速

- ✅ 借鉴源文件 header 双重署名格式正确

### FEATURE_005: DeepSeek V4 Flash 模型架构

#### 需求概述

实现 DeepSeek V4 Flash 完整 forward 路径：MLA（Multi-head Latent Attention）+ HC（Hidden Compression，4 路残差流 + Sinkhorn）+ MoE（256 routed expert，每 token 选 6 + 1 shared expert）+ SwiGLU FFN + RMSNorm + RoPE (YaRN scaling)。

- crate：`rsllm-models`
- 文件：
  - `crates/rsllm-models/src/deepseek_v4_flash.rs`（模型组装）
  - `crates/rsllm-models/src/dsv4/mla.rs`（MLA Q/KV LoRA 投影）
  - `crates/rsllm-models/src/dsv4/hc.rs`（HC pre/post + Sinkhorn 调用）
  - `crates/rsllm-models/src/dsv4/moe.rs`（hash 路由 + topk 路由）
  - `crates/rsllm-models/src/dsv4/shape.rs`（固定形状常量校验）

#### 技术方案

##### 固定形状常量（直接复刻 `ds4.c:81-104`）

```rust

pub const DSV4_HEAD_DIM:          usize = 512;

##### MLA 路径（`ds4.c:1846-1853`）

```
x (n_tok × 4096)
  → attn_q_a:   x → 1024     (LoRA Q 下投影)
  → q_a_norm:   RMSNorm
  → attn_q_b:   1024 → 64×512 (LoRA Q 上投影 + 头分裂)
  → attn_kv:    x → 512      (KV 下投影，1-head)
  → kv_a_norm:  RMSNorm
```

K/Q 尾部 64 维做 RoPE（YaRN scaling），freq_base=160000。

##### HC（Hidden Compression）

```
每个 sublayer 前：
  hc_pre:
    n_tok × 4 × 4096 residual streams
    sinkhorn_mix_20iter → 4×4 mix matrix
    weighted merge → 1 × n_tok × 4096
每个 sublayer 后：
  hc_post:
    broadcast back to 4 residual streams
    accumulate into per-stream output
```

##### MoE 路由

- **前 3 层（hash routing）**：从 `ffn_gate_tid2eid` tensor（`[N_EXPERT_USED=6, N_VOCAB=129280]` i32）直接按 token id 索引 6 个 expert，权重 `sqrt(softplus(logit))` 归一化（`ds4.c:5002-5050`）
- **其余 40 层（topk routing）**：对所有 256 expert 计算 f16 gate logit，取 top-6，权重 `sqrt(softplus)` + L1 归一化（`ds4.c:5088-5097`）
- **Shared expert**：每 token 必激活，不参与 topk 竞争

##### 借鉴源文件 header

```

### FEATURE_006: 三级 KV cache

#### 需求概述

复刻 ds4 的三级 KV cache：
1. **Raw SWA ring**：最近 128 token 的完整 KV，ring buffer
2. **Compressed KV pool**：ratio-2 / ratio-4 池化的历史 KV 行
3. **Ratio-4 Indexer**：对压缩 KV 的稀疏 top-512 attention（128 维，64 头）

KV 数据格式：v0.1.0 在 CPU 路径用 f32（与 ds4 一致），Metal 路径用 FP8 E4M3（F002.1 + F025 联合提供）。

#### 影响范围
- crate：`rsllm-kvcache`
- 文件：
  - `crates/rsllm-kvcache/src/lib.rs`
  - `crates/rsllm-kvcache/src/three_tier.rs`（三级布局）
  - `crates/rsllm-kvcache/src/swa_ring.rs`（SWA 环形）
  - `crates/rsllm-kvcache/src/compressed.rs`（压缩池 + softmax 加权聚合）
  - `crates/rsllm-kvcache/src/indexer.rs`（ratio-4 sparse top-512）

#### 技术方案

##### 数据布局（直接复刻 `ds4.c:5872-5893`）

```rust
pub struct DsV4LayerCache {
    /// 最近 128 token 的完整 KV，f32 row-major，每行 512 维
    pub raw_kv: RingBuffer<KvRow>,
    /// 压缩 KV：每 compress_ratio 个 token 聚合成 1 行
    pub compressed_kv: Vec<KvRow>,
    /// 临时压缩 state（边界触发前），按 ds4 idiom
    pub compress_state_kv: KvRow,
    pub compress_state_score: f32,
    /// ratio=4 层的 indexer 压缩 KV（128 维 × 64 头）
    pub indexer_kv: Option<Vec<IndexerRow>>,
}

pub struct ThreeTierKvCache {
    pub layers: Vec<DsV4LayerCache>,
    pub current_pos: usize,
    pub compress_ratios: Vec<u32>, // 每层独立
}
```

##### 压缩触发（`ds4.c:6154-6206`）

每过 `compress_ratio` 个 token，把 `compress_state_kv` softmax 加权 emit 到 `compressed_kv`，重置 state。

##### Attention 路径

prefill / decode 时 attention 同时读：
- raw_kv 最近 128 token（精确）
- compressed_kv 历史（粗粒度）
- indexer 选出的 top-512 个 compressed 行（细化历史）

##### finish_prefill 状态修剪（`ds4.c:6133-6151`）

prefill 结束时调整 state，让 decode 从正确偏移继续。

#### 接口契约

```rust
impl KvCache for ThreeTierKvCache {
    fn append(&mut self, layer: usize, k: &Buffer, v: &Buffer) -> Result<()>;
    fn read_for_attention(&self, layer: usize) -> ThreeTierView<'_>;
    fn finish_prefill(&mut self, n_tokens: u32);
    fn clear(&mut self);
}

pub struct ThreeTierView<'a> {
    pub raw: &'a [KvRow],        // 最近 128 token
    pub compressed: &'a [KvRow], // 历史压缩
    pub indexer_top_k: Vec<usize>, // 选出的 compressed 行 idx
}
```

#### 内存估算（DS V4 Flash 43 层）

- raw_kv：43 × 128 × 512 × 4B = **11 MiB**（恒定）
- compressed_kv（32k 上下文，平均 ratio=3）：43 × (32k/3) × 512 × 4B ≈ **940 MiB**
- indexer_kv（仅 ratio=4 层，假设 1/3 的层）：14 × (32k/4) × 128 × 64 × 4B ≈ **3.6 GiB**
- **总计 32k 上下文约 4.5 GiB**（vs paged KV 同设置 ≈ 32 GiB；MLA 压缩是核心收益）

#### 实现步骤

1. 实现 `DsV4LayerCache` + `RingBuffer<KvRow>`
2. 实现压缩边界触发（softmax 加权 emit）
3. 实现 ratio-4 indexer（top-512 sparse 选择）
4. 实现 `finish_prefill` 状态修剪
5. 集成进 F005 attention 路径
6. 单元测试：写读一致性、压缩状态正确性
7. 端到端：32k 上下文连续生成不崩、KV 内存占用与公式一致

#### 验收标准

- ✅ 32k 上下文连续生成 1000 token 无错误
- ✅ KV 内存占用与上述公式一致（误差 < 5%）
- ✅ 与 ds4 同 prompt、同种子，KV 内容在 token 级别可重现（中间态校验）
- ✅ `clear()` 后能重新开始 session
