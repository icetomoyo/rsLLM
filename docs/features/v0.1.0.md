## Part A — 版本叙事

### 版本目标

v0.1.0 是 rsLLM 的「**最小可运行**」版本。验收的硬性标准：

```sh
$ rsllm run -m /path/to/llama-2-7b-q4_k_m.gguf -p "Hello, world."
Hello, world. The quick brown fox jumps over the lazy dog. ...
```

能跑出合理输出即算 v0.1.0 通过。**不强调性能**，**不要求 GPU**，**不要求 HTTP server**。

### 本版本范围（In Scope）

1. Cargo workspace 骨架（F001）
2. GGUF 解析器（F002）
3. Tokenizer 集成（F003）
4. CPU 后端基础算子（F004）
5. Llama 2/3 dense 架构（F005）
6. Dense KV cache（F006）
7. 基础采样（F007）
8. CLI `rsllm chat` / `rsllm run` / `rsllm info`（F008）

### 本版本不做（Out of Scope）

- CUDA / Metal 后端（v0.1.1+）
- HTTP server（v0.1.2+）
- MoE 模型（v0.1.4+）
- 量化训练 / 模型转换（永远不做）
- 多 session / 批处理（v0.1.6+）
- 磁盘 KV cache（v0.2.0）

### 技术基线

- Rust edition 2021，rust-version 1.75+（async fn in traits 稳定）
- 严格 `cargo fmt` + `clippy -- -D warnings`
- 单文件 ≤ 800 行
- 公开 API 必须 rustdoc + doctest
- 测试覆盖率（行） ≥ 50%（v0.1.0 阶段，v1.0 时升到 70%）

### MVP 主流程

```
用户：rsllm run -m llama-2-7b.q4_k_m.gguf -p "Hello"
   │
   ▼
[F008 CLI] 解析命令行 → 调用 rsllm-core
   │
   ▼
[F001 Engine] 加载模型
   │
   ├─► [F002 GGUF] mmap 文件 + 解析 metadata + tensor info
   ├─► [F003 Tokenizer] 从 GGUF metadata 加载 tokenizer + chat template
   ├─► [F005 Llama] 识别架构 → 实例化 Llama 模型图
   └─► [F004 CPU Backend] 为每个 tensor 分配 / 包装设备缓冲
   │
   ▼
[F003] tokenize prompt → token IDs
   │
   ▼
循环：
  [F005 Llama.forward] → 调用 [F004 CPU ops]
       → [F006 KV cache] 读写
  [F007 Sampler] sample token from logits
  [F003] decode token → 字符串 → 打印
  直到 EOS 或 max_tokens
   │
   ▼
退出
```

### 验收标准（版本级）

- ✅ `cargo build --release` 在 Linux x86_64 + macOS arm64 上成功
- ✅ `cargo test --workspace` 全部通过
- ✅ `cargo clippy --workspace -- -D warnings` 通过
- ✅ `cargo fmt --check` 通过
- ✅ `rsllm run -m <gguf> -p "Hello"` 能输出合理 token 序列
- ✅ Tokenizer 在 100 句测试集上与官方 tokenizer 一致
- ✅ CI 矩阵：ubuntu-latest + macos-latest 全绿

### FEATURE_002: GGUF 文件解析器

> **状态**：✅ **Completed**（2026-05-14）
> 已落地 9 种 v0.1.0 量化解码（F32 / F16 / BF16 / Q4_0 / Q4_1 / Q4_K / Q5_K / Q6_K / Q8_0），83 个单元测试 + 2 个端到端集成测试全绿。MSRV 升级到 1.87 以使用稳定的 `is_multiple_of` / `div_ceil`。

#### 需求概述
自实现 GGUF v3 文件格式解析器，支持 mmap 零拷贝加载，**不**链接 ggml/llama.cpp。借鉴 candle 的 `gguf_file.rs` Rust 风格，借鉴 ds4 `ds4.c:217-298` 的量化解码常量与查找表。

#### 影响范围
- 新增 crate：`rsllm-gguf`
- 文件：
  - `crates/rsllm-gguf/src/lib.rs`
  - `crates/rsllm-gguf/src/header.rs`（magic、version、kv metadata）
  - `crates/rsllm-gguf/src/tensor.rs`（tensor info、dequant trait）
  - `crates/rsllm-gguf/src/quants/`（按量化格式分文件）
  - `crates/rsllm-gguf/tests/`（端到端解析测试）

#### 技术方案

##### 支持的量化格式（v0.1.0 范围）
- F32 / F16 / BF16（无量化）
- **Q4_0 / Q4_1**（legacy 4-bit，旧版 Llama 2 GGUF 大量使用，必须支持）
- Q4_K_M / Q4_K_S（4-bit K-quants）
- Q5_K_M / Q5_K_S（5-bit）
- Q6_K（6-bit）
- Q8_0（8-bit）

##### 不支持（推迟到 v0.1.x / v0.2.0）
- Q2_K / Q3_K_M / IQ2_XXS / IQ3_XXS（v0.2.0 MoE 用；**注**：F014 Mixtral 跑通**依赖**这些格式，需要 v0.1.4 前补齐，否则 F014 验收目标改为 Phi-3.5-MoE）
- FP8 E4M3FN（v0.2.0 DeepSeek-V3 用）
- GPTQ / AWQ（v0.2.x）

##### IQ2_XXS / IQ3_XXS（v0.1.4 启动前 1 周补齐）
- F014 (Phi-3.5-MoE) 的专家权重格式可能包含 IQ2_XXS / IQ3_XXS
- 借鉴 `ds4.c:217-298` 的 320 行查找表常量
- 严格来说不是 v0.1.0 的范围，但**作为 F014 前置依赖**，必须在 v0.1.4 启动前补齐
- 实现成本：1 周（查找表 + dequant 函数 + 测试）

##### 模型指纹（FEATURE_022 KVC v2 依赖）
- 在解析完 header + tensor index 之后，计算 `sha256(tensor_layout_canonical_bytes)` 作为模型指纹
- 用途：磁盘 KV cache 索引键的一部分，防止不同模型误用同一份 KV
- 不计算整个权重 hash（成本太高），只 hash 元数据规范化字节流

##### 平台特殊：macOS mmap MAP_PRIVATE
- Darwin 内核存在 VM map-count accounting bug（参考 `ds4.c:1188-1200`）
- 大型 GGUF 用 `MAP_SHARED` 在 macOS 上可能触发 kernel panic
- **必须**在 `cfg(target_os = "macos")` 下强制 `MAP_PRIVATE`
- Linux/Windows 默认 `MAP_SHARED` 即可

##### 关键设计
- `GgufFile`：mmap 的 `Mmap` 句柄 + 解析后的 metadata + tensor index
- `Tensor::data() -> &[u8]`：返回原始字节切片（零拷贝）
- `dequant_to_f32(&self, dst: &mut [f32])`：解量化到目标缓冲
- 全部通过 `&[u8]` 操作，**禁止** `Vec<f32>` 拷贝整个权重

##### 借鉴策略
- 文件 header 部分：参考 [candle gguf_file.rs](https://github.com/huggingface/candle)（Apache 2.0 致谢）
- 量化 block 布局：参考 ggml `ggml-quants.h`（MIT 致谢）
- 解码查找表常量：参考 ds4 `ds4.c:217-298`（MIT 致谢）
- 每个 quants 文件 header 加双重署名

#### 接口契约

```rust
pub struct GgufFile { /* opaque */ }

impl GgufFile {
    pub fn open<P: AsRef<Path>>(path: P) -> Result<Self, Error>;
    pub fn metadata(&self) -> &Metadata;
    pub fn tensor(&self, name: &str) -> Option<&TensorInfo>;
    pub fn tensors(&self) -> impl Iterator<Item = &TensorInfo>;
}

pub struct TensorInfo {
    pub name: String,
    pub shape: Vec<u64>,
    pub dtype: GgmlType,
    pub data: &[u8],  // mmap 切片
}

pub trait Dequant {
    fn dequant_to_f32(data: &[u8], shape: &[u64], dst: &mut [f32]);
}
```

#### 实现步骤

1. 实现 `Header` 解析（magic 验证、version 检查、kv metadata 读取）
2. 实现 `TensorInfo` 解析（按 alignment 对齐定位 tensor 数据）
3. 实现 mmap 加载，**macOS 强制 MAP_PRIVATE**（cfg gate）
4. 实现模型指纹：`sha256(tensor_layout_canonical_bytes)`
5. 实现 F32 / F16 / BF16 dequant（最简单的）
6. 实现 Q8_0 / Q4_0 / Q4_1 / Q4_K dequant（最常用量化）
7. 实现 Q5_K / Q6_K dequant
8. 写解析器单元测试（用小型 GGUF 文件 fixture）
9. 写端到端测试：加载 Llama 2 7B Q4_K_M 文件，验证 tensor 数量、shape、采样几个值正确

#### 验收标准

- ✅ 能加载官方 `llama-2-7b.q4_k_m.gguf` 不崩
- ✅ 能加载 legacy `llama-2-7b.q4_0.gguf` 不崩（Q4_0 路径覆盖）
- ✅ tensor 数量 = 291（Llama 2 7B 的标准 tensor 数）
- ✅ Q4_K_M / Q4_0 dequant 输出与 llama.cpp 参考输出在 1e-3 误差内（10 个采样 tensor / 各量化各一组）
- ✅ mmap 加载 7B 模型 RSS 增长 < 50MB（确认零拷贝）
- ✅ macOS 上 mmap 7B 模型不触发 kernel panic（用 `MAP_PRIVATE` 验证）
- ✅ `GgufFile::model_fingerprint() -> [u8; 32]` 对同一文件稳定返回相同值
- ✅ 单元测试覆盖率 ≥ 70%
- ✅ 文件 header 双重署名格式正确

### FEATURE_003: Tokenizer 集成

#### 需求概述
集成 HuggingFace `tokenizers` crate，从 GGUF metadata 加载 tokenizer 配置，应用 chat template，输出 token IDs。

#### 影响范围
- 新增 crate：`rsllm-tokenizer`
- 依赖：`tokenizers = "0.20"`、`minijinja = "2"`（chat template 渲染）

#### 技术方案

- GGUF metadata 内嵌 tokenizer vocab + merges（BPE）或 SentencePiece model
- 我们从 `tokenizer.ggml.model`、`tokenizer.ggml.tokens`、`tokenizer.ggml.merges` 等 kv 重建 `tokenizers::Tokenizer`
- 备选：用户可指定外部 `tokenizer.json` 路径
- Chat template 从 `tokenizer.chat_template` kv 读取，用 minijinja 渲染

#### 接口契约

```rust
pub struct Tokenizer { /* opaque */ }

impl Tokenizer {
    pub fn from_gguf(meta: &Metadata) -> Result<Self, Error>;
    pub fn from_json<P: AsRef<Path>>(path: P) -> Result<Self, Error>;
    pub fn encode(&self, text: &str) -> Result<Vec<u32>, Error>;
    pub fn decode(&self, ids: &[u32]) -> Result<String, Error>;
    pub fn apply_chat_template(&self, messages: &[Message]) -> Result<String, Error>;
    pub fn eos_token_id(&self) -> u32;
    pub fn bos_token_id(&self) -> Option<u32>;
}
```

#### 实现步骤

1. 实现 `from_gguf` —— 解析 GGUF tokenizer kv，重建 tokenizers crate 的 BPE/Unigram 模型
2. 实现 `from_json` —— 直接加载 HF tokenizer.json
3. 实现 chat template 渲染（minijinja）
4. 写单元测试：encode/decode 一致性、特殊 token 处理
5. 写一致性测试：与 HF python tokenizer 在 100 句测试集上 100% 一致

#### 验收标准

- ✅ 能从 Llama 2 7B GGUF 加载 tokenizer
- ✅ 在 100 句测试集（含 emoji / 中英文混合 / 特殊字符）上与 HF tokenizer 100% 一致
- ✅ Chat template 应用与 HF transformers `apply_chat_template` 一致

### FEATURE_004: CPU 后端基础算子

#### 需求概述
实现 CPU 后端的基础线性代数与神经网络算子：matmul、rmsnorm、rope、softmax、sigmoid、SwiGLU。支持 AVX2（x86_64）和 NEON（aarch64）SIMD 加速。

#### 影响范围
- 新增 crate：`rsllm-backend-cpu`
- 实现 `rsllm-cal::Backend` trait
- 借鉴：ggml CPU SIMD kernels（MIT）、ds4 ARM NEON 路径（MIT）

#### 技术方案

##### 算子清单（v0.1.0 范围）
- `matmul_f32` / `matmul_q4_k_f32`（量化权重 × f32 激活）
- `rmsnorm`
- `rope`（含 YaRN scaling 占位）
- `softmax`（含 attention masking）
- `silu`（SwiGLU 的激活部分）
- `embedding_lookup`
- `add` / `mul` / `scale`
- `argmax`（贪心采样辅助）

##### SIMD 策略
- 编译期 `cfg(target_arch = "x86_64")` + `is_x86_feature_detected!("avx2")` 启动期分发
- ARM NEON 用 `std::arch::aarch64`
- 兜底标量实现
- 借鉴 ggml 的 dot product 实现，文件 header 双重署名

##### 量化 matmul
- 不解量化全权重，而是在 kernel 内边读边解
- Q4_K_M：每 256 元素一个 super-block，6 个 scale + 32 个 4-bit weight
- 借鉴 ggml `ggml_vec_dot_q4_K_q8_K`

#### 接口契约

实现 `Backend` trait（来自 `rsllm-cal`），具体 op enum：

```rust
pub enum CpuOp {
    Matmul { lhs_dtype: DType, rhs_dtype: DType, /* ... */ },
    RmsNorm { eps: f32 },
    Rope { theta: f32, scale: RopeScale },
    Softmax { mask: bool },
    Silu,
    /* ... */
}
```

#### 实现步骤

1. 实现 `Backend` trait + buffer / stream 类型
2. 实现 f32 标量版本所有算子（正确性优先）
3. 添加 AVX2 fast path 给 matmul / rmsnorm
4. 添加 NEON fast path（Mac M1+ 测试）
5. 实现 Q4_K_M 量化 matmul
6. 单元测试：每个算子与 numpy / candle 参考实现对齐（1e-4）

#### 验收标准

- ✅ 所有算子单元测试通过
- ✅ Q4_K_M matmul 在 4096×4096 矩阵上 AVX2 加速 ≥ 3× 标量
- ✅ Q4_K_M matmul 与 ggml 输出在 1e-3 误差内
- ✅ 借鉴源文件 header 双重署名格式正确

### FEATURE_005: Llama 模型架构

#### 需求概述
实现 Llama 2 / Llama 3 / Llama 3.1 / Llama 3.2 的 dense 架构（不含 MoE）。使用 FEATURE_004 的算子组装 forward pass。

#### 影响范围
- 新增 crate：`rsllm-models`
- 文件：`crates/rsllm-models/src/llama.rs`、`common/{rms_norm.rs, rope.rs, attention.rs, mlp.rs}`

#### 技术方案

##### 架构要点
- Decoder-only transformer
- GQA（Grouped Query Attention）：n_heads / n_kv_heads 可能不相等
- RoPE position embedding，**rope_freq_base 从 GGUF 动态读取**（Llama 2 = 10000，Llama 3+ = 500000，不可硬编码）
- YaRN scaling（Llama 3.1+ 128k 上下文必需，参数 `rope.scaling.type / .factor / .original_context_length`）
- RMSNorm（不是 LayerNorm）
- SwiGLU FFN
- 无 bias 在大多数 linear 层
- **Tied embedding**（Llama 3.2 1B/3B 使用 lm_head = token_embd 权重共享，加载时若 GGUF 不含 `output.weight` 张量则走 tied 路径）

##### 关键家族差异表

| 项 | Llama 2 7B | Llama 3.1 8B | Llama 3.2 1B/3B |
|---|---|---|---|
| vocab_size | 32000 | 128256 | 128256 |
| rope_freq_base | 10000 | 500000 | 500000 |
| n_kv_heads | 32 | 8 | 8/8 |
| max_ctx (训练) | 4096 | 131072 | 131072 |
| tied embedding | 否 | 否 | **是** |
| YaRN scaling | 否 | 是 | 是 |
| tokenizer | SentencePiece | tiktoken-style BPE | tiktoken-style BPE |

##### 模型配置从 GGUF metadata 加载
- `llama.block_count` → n_layers
- `llama.embedding_length` → d_model
- `llama.feed_forward_length` → ffn_hidden
- `llama.attention.head_count` → n_heads
- `llama.attention.head_count_kv` → n_kv_heads
- `llama.attention.layer_norm_rms_epsilon` → rms_eps
- `llama.rope.freq_base` → rope_theta（**不硬编码 10000**）
- `llama.rope.scaling.type` / `.factor` / `.original_context_length` → YaRN 参数（Llama 3.1+）
- `llama.vocab_size` → vocab_size
- 加载 lm_head：先找 `output.weight`，找不到则**复用** `token_embd.weight`（tied embedding 路径）

### FEATURE_006: KV cache 基础

#### 需求概述
最简单的 dense KV cache：每层一个大连续 buffer，按 (n_layers, 2, max_seq_len, n_kv_heads, head_dim) 形状预分配。单 session，不分页，不持久化。

#### 影响范围
- 新增 crate：`rsllm-kvcache`
- 后续 v0.1.1 会改造为 Paged

#### 技术方案

- `KvCache::new(config, backend)` 一次性分配
- `KvCache::append(layer_idx, k, v)` 追加当前 token
- `KvCache::slice_up_to(layer_idx, len)` 给 attention 用
- 内存公式：`2 × n_layers × max_seq_len × n_kv_heads × head_dim × sizeof(f16)`
- **示例**（Llama 3.1 8B，n_layers=32，n_kv_heads=8，head_dim=128，f16）：
  - 4k 上下文：2 × 32 × 4096 × 8 × 128 × 2 = **256 MiB**
  - 32k 上下文：**2 GiB**
  - 128k 上下文：**8 GiB**（接近单卡 4090 24GB 的 1/3，长上下文必须 paged，v0.1.1）
- **接口预留 sliding window**：v0.1.0 不实现，但接口字段必须存在，避免 v0.1.3 加 Mistral 7B v0.3（默认 SWA=4096）时破坏向下兼容

#### 接口契约

```rust

    pub layout: KvLayout,                  // v0.1.0 只支持 Dense；Paged/Mla/SlidingWindow 是后续 feature
    pub dtype: DType,                      // f16

}

    pub fn append(&mut self, layer: usize, k: &Buffer, v: &Buffer) -> Result<()>;

    pub fn v_so_far(&self, layer: usize) -> BufferSlice;

    pub fn clear(&mut self);
}
```

#### 实现步骤

2. 实现 `append` 写入
3. 实现 `slice_up_to` 切片视图（不拷贝）
4. 集成进 Llama attention（FEATURE_005）
5. 单元测试：写读一致性、容量边界

#### 验收标准

- ✅ Llama 2 7B 4k 上下文连续生成 100 token 无错误
- ✅ KV cache 内存占用与公式一致（误差 < 5%）
- ✅ `clear()` 后能重新开始 session

### FEATURE_007: 采样器

#### 需求概述
从 logits 采样下一个 token。支持 greedy / temperature / top-k / top-p / **min-p** / repetition penalty。OpenAI API 兼容字段 `frequency_penalty` / `presence_penalty` 在 v0.1.0 接受参数但**不实际生效**（v0.1.x 补全），不报错。

#### 影响范围
- 新增模块：`rsllm-core/src/sampler.rs`

#### 技术方案

- 链式过滤器：repetition_penalty → temperature → top-k → top-p → **min-p** → multinomial
- min-p（参考 ds4 `ds4.c:14248-14343`）：截断概率小于 `min_p × max_prob` 的 token，对低温场景比 top-p 更稳
- 用 `rand` crate 做随机采样
- 种子可控（便于 reproducible 测试）；未指定时用基于时间的默认种子

#### 接口契约

```rust
pub struct SamplingParams {
    pub temperature: f32,                  // 0.0 = greedy
    pub top_k: Option<usize>,
    pub top_p: Option<f32>,
    pub min_p: Option<f32>,                // 新增：ds4 server 标准参数
    pub repetition_penalty: Option<f32>,
    pub seed: Option<u64>,                 // None = time-based 默认
    // OpenAI 兼容字段（v0.1.0 接受但不生效，warn 一次）
    pub frequency_penalty: Option<f32>,
    pub presence_penalty: Option<f32>,
}

pub struct Sampler { /* opaque */ }

impl Sampler {
    pub fn new(params: SamplingParams) -> Self;
    pub fn sample(&mut self, logits: &mut [f32], history: &[u32]) -> u32;
}
```

#### 实现步骤

1. 实现 greedy（argmax）
2. 实现 temperature scaling
3. 实现 top-k（partial sort）
4. 实现 top-p（cumulative sum）
5. 实现 min-p（参考 ds4 实现，按 max_prob × min_p 截断）
6. 实现 repetition penalty
7. 实现 multinomial（带种子可控）
8. 对 `frequency_penalty / presence_penalty` 非 None 时 `tracing::warn!` 一次（"accepted but not implemented in v0.1.0"）
9. 单元测试：每个过滤器单独测试 + 组合测试

#### 验收标准

- ✅ 同种子下 sample 结果可复现
- ✅ Greedy 与 HF transformers `do_sample=False` 输出一致
- ✅ Temperature=1.0 + top-k=50 + top-p=0.9 与 HF 行为统计一致
- ✅ min_p=0.05 + temperature=0.7 在 ds4 同种子同 prompt 下输出一致
- ✅ 传入 `frequency_penalty=1.5` 不报错，但生成 warn 日志

### FEATURE_008: CLI 入口

#### 需求概述
`rsllm` 二进制提供四个子命令：`chat`（交互 REPL）、`run`（一次性）、`info`（系统能力探测）、`inspect`（模型 tensor 详情）。`run` 子命令额外支持 `--dump-tokens` / `--dump-logprobs` 调试输出，这是 F003 / F005 验收的关键基础设施。

#### 影响范围
- crate：`rsllm-cli`
- 依赖：`clap = "4"`、`rustyline = "14"`（REPL）

#### 技术方案

##### 子命令
- `rsllm info [-m <gguf> -c <ctx>]` —— 输出 OS、CPU 特性、可用后端、Rust 版本；带 `-m` 时额外输出该模型在指定上下文下的预估内存
- `rsllm inspect -m <gguf>` —— 输出模型 tensor 列表（name / shape / quant / bytes）、metadata、量化格式分布、模型指纹（SHA256）。参考 ds4 `model_summary()` (`ds4.c:1229-1300`)
- `rsllm run -m <gguf> -p <prompt> [--max-tokens N] [--temp T] [--top-p P] [--min-p P] [--seed N]`
- `rsllm run` 调试参数：
  - `--dump-tokens` —— 把每步 token id 和文本片段打印到 stderr（用于 tokenizer 一致性比对）
  - `--dump-logprobs <FILE> [--logprobs-top-k N]` —— 把每步的 top-K logit + 选择的 token 写入 JSON 文件，可与 HF transformers `generate(output_scores=True)` 输出做数值比对
  - 参考 ds4 `ds4_cli.c:35-37` 的 `dump_logprobs_path / dump_logprobs_top_k / dump_tokens` 字段，按 MIT 致谢
- `rsllm chat -m <gguf> [--system <sys-prompt>] [--max-tokens N]`

##### Chat REPL
- 多行输入支持（`/edit` 触发外部编辑器）
- 命令：`/help`、`/clear`、`/quit`、`/system "..."`
- Ctrl+C 中断生成
