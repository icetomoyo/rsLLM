# v0.1.x Roadmap（v0.1.1 → v0.1.9）

> 总览：v0.1.0 骨架完成后，9 个 patch 版本逐步把 rsLLM 从 CPU-only 推到「CUDA + HTTP API + 多模型 + MoE + 连续批处理 + Metal 基础版 + Prefix Cache + 磁盘 KV 简化版 + TP」。
>
> 每个 patch 的详细 6 节 feature 设计在该 patch 启动前由 `/start-next-feature` 触发补写到对应 `vX.X.X.md` 文件。本文是高层全局视图。
>
> **修订**：本路线在 2026-05-11 review 后调整，详见 [`v0.1.0.md#修订记录`](v0.1.0.md#修订记录)。

---

## v0.1.1 — CUDA 启动 + Paged KV

**主线**：把 CPU 后端验证过的模型搬到 NVIDIA GPU 上。

**Features**：
- **F009** CUDA 后端基础（cudarc + 借鉴 ggml-cuda kernel）
- **F010** Paged KV cache（vLLM 风格 block 管理，块大小 16/32 可配）

**前置 ADR**：
- ADR-0002：CUDA 绑定选 cudarc（运行时加载，不静态链接 CUDA toolkit）

**验收**：
- Llama 3.1 8B Q4_K_M 在 4090 上 ≥ 95 t/s（先达到 llama.cpp 基线）
- KV OOM 时优雅降级（不崩溃）

---

## v0.1.2 — 服务化（OpenAI API）

**主线**：HTTP server + 流式 + 模型管理基础。

**Features**：
- **F011** OpenAI Chat Completions API + SSE 流式
- **F012** axum HTTP server（含 `/healthz`、`/v1/models`、基础限流）

**验收**：
- `pytest openai-python` 主流测试用例通过
- Open WebUI / OpenAI Python SDK 兼容
- 24h 跑测不崩溃，内存稳定

---

## v0.1.3 — 多模型家族

**主线**：扩展到 Llama 之外的主流家族。

**Features**：
- **F013** Qwen / Mistral / Phi 支持
  - Qwen 2.5 7B / 14B / 32B（tiktoken BPE，pre-tokenizer `qwen2`）
  - Mistral 7B v0.3（**激活 v0.1.0 预留的 sliding window 字段**）
  - Phi-3.5-mini（SwiGLU，标准架构）

**验收**：
- 三家族各跑通官方 GGUF + tokenizer 100% 一致

---

## v0.1.4 — MoE 试水（Phi-3.5-MoE）

**主线**：第一次跑 MoE。

**Features**：
- **F014** MoE 模型支持，验收目标 **Phi-3.5-MoE（16x3.8B，Q4_K_M ≈ 10GB，4090 能装）**
  - **Mixtral 8x7B 暂不验收**（26GB > 24GB 物理不可），等 v0.2.0 F019 异构调度

**前置依赖（v0.1.4 启动前 1 周补齐）**：
- F002 GGUF 补 **IQ2_XXS / IQ3_XXS** dequant（借鉴 ds4 `ds4.c:217-298` 查找表）

**验收**：
- Phi-3.5-MoE Q4_K_M 在 4090 上 ≥ 25 t/s

---

## v0.1.5 — 连续批处理 ⭐ 调整后提前

**主线**：单 GPU 服务化的核心能力。

**Features**：
- **F016** Continuous Batching（参考 vLLM 风格）
  - chunked prefill（按 token budget 打包请求）
  - 抢占式调度

**验收**：
- 32 并发请求吞吐 ≥ 单请求 6×
- P99 / P50 延迟比 ≤ 2.5×

---

## v0.1.6 — Mac 第一波（Metal 基础内核）⭐ 调整后从 v0.2.0 提前

**主线**：让 Mac 用户能用 GPU，结束 v0.1.x 期间 Mac 只能跑 CPU 的窘境。

**Features**：
- **F025** Metal 基础内核
  - matmul（含量化路径）
  - attention（朴素版本，非 flash）
  - rope / rmsnorm / softmax / silu
  - 借鉴 ggml `ggml-metal.m`（MIT）+ MLX 优化模式（MIT）

**不在 v0.1.6 范围**（推到 v0.2.0 F032 完整版）：
- Flash Attention（v1/v2/v3）
- MoE matvec for IQ2_XXS / Q2_K
- FP8 KV cache quantization
- Hyper-Connection kernel

**验收**：
- Llama 3.1 8B Q4_K_M 在 M3 Max 上 ≥ 35 t/s
- Llama 70B Q4_K_M 在 M3 Max 128GB 上 ≥ 8 t/s（完整版 F032 目标 ≥ 10 t/s）

**前置 ADR**：
- ADR-0008：Metal 绑定选 `objc2` + `objc2-metal`

---

## v0.1.7 — Prefix Cache

**主线**：跨 session 复用相同前缀的 KV，agent 场景显著提速。

**Features**：
- **F017** Radix tree prefix cache
  - 节点 = token 序列段 + KV block 引用
  - LRU 淘汰，全局 block table

**验收**：
- agent 场景下平均节省 ≥ 60% prefill 计算
- 多 session 共享 prefix 时无数据竞争

---

## v0.1.8 — Agent 基础（磁盘 KV cache 简化版）⭐ 调整后从 v0.2.0 提前

**主线**：解决 agent 工作流"每次开新会话都重 prefill"的痛点。

**Features**：
- **F022** 磁盘 KV cache 简化版（**仅 cold checkpoint**）
  - KVC v2 文件格式（参考 ds4 KVC，加版本/模型指纹/CRC）
  - 索引：B-tree on `sha256(token_ids[:N])` → KvcFileId
  - LRU 淘汰，`--kv-disk-space-mb` 配置上限
  - **只做 cold checkpoint**：会话结束时落盘，下次同 prefix 命中时加载

**不在 v0.1.8 范围**（推到 v0.2.0 F031 完整版）：
- Continued checkpoint（会话进行中阶段性保存）
- Tool call replay map

**依赖**：
- F002 模型 SHA256 指纹（v0.1.0 已规划）

**验收**：
- 25k token 系统提示 cold 命中时首 token 延迟 ≤ 100ms
- 跨进程重启缓存仍命中

## v0.1.9 — 多 GPU + 可观测性 ⭐ TP 顺序调整后

**主线**：v0.1 系列收尾，为 v0.2.0 准备。

**Features**：
- **F015** Tensor Parallel（单机多 GPU）
  - 按 head / FFN intermediate dim 切
  - NCCL FFI 或 cudaIpc + 自实现（ADR 待写）
- **F018** Prometheus metrics + OpenTelemetry traces

**验收**：
- 双 4090 TP 跑 Llama 70B FP16 ≥ 12 t/s
- 关键指标暴露：吞吐 / 延迟 / KV 内存 / 队列深度 / GPU 内存
